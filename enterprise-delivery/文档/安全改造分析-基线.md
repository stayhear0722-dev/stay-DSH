# dsh-lark 自建部署安全能力基线（对照 WorkBuddy / 千问办公）

> 用途：公司信息安全手册到手后，把手册要求逐条合并进本文件，产出最终「需要改造的安全项清单」。
> 本文档的 dsh-lark 部分已对照源码核实（`C:\Path\To\ApprovedWorkspace\dsh-lark`，v0.0.6）。

## 一、dsh-lark 现状安全能力（源码已核实）

### 开箱即有（配置即可）
| 能力 | 配置/机制 | 对应企业安全需求 |
|---|---|---|
| 私聊白名单 | `senderAllowlist`（ou_ open_id 列表） | 最小权限、用户准入 |
| 群白名单 | `groupAllowlist`（oc_ chat_id 列表） | 群边界管控 |
| 审批人白名单 | `approvers`（谁才能批准工具/计划） | 审批权分离、职责分离 |
| 需 @ 才响应 | `requireMention`（默认 true） | 防误触发 |
| 文件系统边界 | `workspaceRoots`（/cd 可切换目录前缀） | 防文件漫游 |
| 工具禁用 | `denyTools`（按 Agent 执行时拒绝并说明） | 高危操作管控 |
| 机器人轮次上限 | `botPeers` / `botHops`（默认 6 轮） | 防 Bot 死循环、资源滥用 |
| 图片不投喂模型 | `attachImages` 默认 false | 数据防泄露 |
| 会话隔离 | `sessionScope`：chat / chat-thread / chat-sender | 多租户数据隔离 |
| 密钥不落明文 | `appSecretRef` 走宿主凭据 seam（env/dotenv/凭据服务） | 密钥管理 |
| 模型 key 保护 | 走宿主凭据存储，不写进 unit 文件；unit 0600 | 密钥管理 |
| 审批防串台 | 卡片绑定原聊天 + correlation id | 防越权操作 |
| 传输安全 | 飞书长连接（出站），无公网监听端口；dmMode allowlist | 网络边界 |

### 缺失（需改造/自建）
| 缺失项 | 说明 | 改造路径 |
|---|---|---|
| 审计日志 | 仅启动时打印一行授权边界；无「谁在何时让 Agent 执行了什么」 | fork 后在 bridge.ts 单点挂审计钩子，落库或对接企业日志平台 |
| DLP / 敏感词 / 脱敏 | 无内容过滤 | 二次开发内容过滤中间件 |
| 模型输出审查 | 可固定 provider/model 路由，但无输出审查 | host 侧或企业网关 |
| 动态审批流 | approvers 为静态 open_id 列表 | 对接飞书原生审批或自研审批服务 |
| KMS/Vault 适配 | 凭据 seam 是替换点但无内置适配器 | 写 Vault/KMS 凭据 provider（接口仅 resolve/set） |
| 认证背书 | 无等保/信通院/ISO 认证 | 走企业合规流程 |
| 漏洞管理 | 自维护，SECURITY.md 只修最新版 | 建立升级/补丁节奏 |
| Windows 常驻 | 无 launchd/systemd 时 start 退化为前台运行 | 自行包装服务 |

## 二、对标基线（商业产品）

### WorkBuddy（腾讯）
- 部署形态：SaaS / VPC / 私有化一体机（沐曦+腾讯一体机，政务落地，支持国产芯片）
- 模型：厂商模型（私有化版可数据不出域）
- 安全卖点：信通院等认证、Prompt 防护、数据隔离
- 供应链：腾讯 SRE 兜底
- 局限：平台级黑盒，定制受限

### 千问办公（阿里通义）
- 部署形态：以 SaaS 为主，多端（含鸿蒙）
- 模型：通义千问系列
- 安全卖点：国内首个通过中国信通院办公智能体能力评估（企业数据安全、风险管理达标）
- 供应链：阿里 SRE 兜底
- 局限：SaaS 数据链路经阿里侧，定制受限

### 自建（dsh-lark + DeepSeek Harness）优劣势
- 优势：数据不出域、全代码可控（BSD-3-Clause）、源码级细粒度权限、可对接企业基础设施（KMS/审计/DLP）、模型可自托管
- 劣势：无认证背书、无内置审计/DLP/输出审查、自维护（漏洞/补丁/应急）
